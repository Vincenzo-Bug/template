# Security Policy

This repository is a starter foundation, not a production authorization or
compliance implementation. Before deployment, define a project-specific threat
model, authentication and authorization design, data classification, retention
policy, incident process, and dependency update policy.

Do not commit real credentials. Report a suspected vulnerability privately to
the repository owner with reproduction steps and impact; do not open a public
issue containing sensitive details.

The template includes secret-redacting settings, safe error responses,
non-root containers, dependency scanning, and a conservative deny set for
future automation. These controls are a baseline, not a substitute for product
security review.
